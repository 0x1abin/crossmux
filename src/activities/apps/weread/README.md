# 微信读书

CrossMux 的非官方微信读书客户端，用于扫码登录、同步个人书架，并将书籍缓存为 EPUB 供内置阅读器离线阅读。

## 功能与使用

- 统一固件始终编译；仅在 China 内容区域显示。
- 从 **Apps → 微信读书** 进入。没有有效本地会话时会先显示免责声明；选择“同意”后才会联网，返回则退出到 Apps。已有有效会话时会优先直接打开本地书架。
- 首页使用 **书架 / 管理** 两个顶部标签。书架显示按最近阅读时间排列的均匀封面网格，竖屏每页 3×3 本、横屏每页 5×2 本；管理包含刷新书架、清除缓存和退出登录。首次登录、本地书架缺失或翻页后只补取当前页封面。刷新书架会询问是否完整缓存所有封面；选择“否”后继续按页缓存，选择“是”则分阶段补齐全部缺失封面，并显示详情、原图和缩略图处理进度。书架超过 500 本时不执行全量封面批处理，仍按当前页补取。单本失败会显示占位图，取消会保留已完成封面并显示部分书架。
- 选择书籍后会缓存文字详情、原始封面和最大 112×164 的封面缩略图；详情页仍按 96×140 显示。文字先显示，封面随后加载。
- 书籍详情页的 **划线书评** 可浏览该书的热门划线、我的划线和热门书评，全文使用阅读器当前选择的字体和字号。首次进入会一次性缓存三类数据；热门书评最多缓存服务端排序的前 50 条。缓存完成后可离线浏览，选择“重新缓存”可拉取最新快照；返回键按全文、列表、划线书评菜单、书籍详情的顺序逐级返回。该入口只读，不点赞、评论、修改划线或写入 EPUB。
- 详情页可选择是否缓存正文图片，再将整本书缓存为 EPUB。生成的 EPUB 始终包含可用封面，并过滤书内脚注的引用与正文，避免不受支持的脚注混入阅读正文；正文图片下载失败会跳过该图，章节或 SD 写入失败则中止整本缓存。升级到包含此修复的固件后，需重新缓存受影响的书籍以覆盖 `/WeRead` 中保留的旧 EPUB。
- 缓存完成后的 EPUB 保存在 `/WeRead/<书名>-<bookId>.epub`，可由内置阅读器断网打开。在线阅读入口当前显示为“即将支持”，不会联网或生成窗口 EPUB。
- 阅读已缓存的标准微信读书 EPUB 后，手动执行阅读器中的“同步进度”会同时上报刚结束的本次阅读时长。双方进度一致或选择云端进度时也会上报；失败可在当前同步界面重试，但离开后不保留待上传时长。公众号文章和普通本地 EPUB 不参与时长上报。
- 打开微信读书不会因固件升级自动扫描或清空全局缓存；章节缓存通过自身版本在用户缓存书籍时逐章更新。管理标签中的 **清除缓存** 会删除书架列表、封面、详情、章节、图片、划线书评、旧版升级标记和临时数据，但保留登录状态、免责声明确认、`/WeRead` 中已缓存的 EPUB 及其阅读进度。
- 退出登录会返回扫码流程。

构建 X3/X4 统一语言固件（选择简体中文启用 China 内容区）：

```sh
pio run -e gh_release
```

## 代码与数据

| 文件 | 职责 |
|---|---|
| `webapi/WeReadActivity.*` | 界面、按键和任务状态流 |
| `webapi/WeReadBrowseActivity.*` | 划线书评菜单、列表和正文浏览 |
| `WeReadActivity.h`、`WeReadProgressSyncActivity.h`、`WeReadBackend.h` | 编译期选择入口 |
| `lib/WeReadWebApi` | 登录、HTTP、协议解析、缓存、划线书评和 EPUB 打包 |

登录会话、书架、详情、章节、图片和缓存中间数据保存在 SD 卡的 `/.crosspoint/weread/`。详情、原始封面和章节缓存可复用；最大 112×164 的封面只读取 `cover.v2.bmp`，旧 `cover.bmp` 不再读取或迁移。旧章节缺少图片索引时会重新拉取。每本书的图片策略只在 EPUB 成功生成后保存。`session.bin` 含登录会话信息，请妥善保管 SD 卡；退出登录会清除本地会话和书架索引，已缓存的 EPUB 会保留。

书架封面批处理用于首次预取 10 本或用户选择完整缓存时：先复用微信 API 的同主机 TLS 补取详情，再复用图片 CDN 的同主机 TLS 下载原图，最后关闭 TLS 后统一转换缩略图。三个阶段都逐本流式读写 SD 卡，不在内存中保存整批封面；主机变化或服务端关闭连接时会自动重连。

划线书评只使用扫码登录得到的 Web Cookie，不需要 Skill API Key，也不会切换到 Agent Gateway。缓存位于 `/.crosspoint/weread/browse-cache/<bookId>/`：刷新先写非活动槽，三类数据全部成功并验证后才原子切换清单，因此失败、取消或断电不会替换上次完整快照。缓存绑定当前 `wr_vid`，退出登录或登录账号变化时清除；退出应用和设备重启不会清除。旧的 `/.crosspoint/weread/browse/` 临时目录只做遗留清理，不迁移。

整批缓存依次请求热门划线、我的划线和热门书评，正常情况下复用同一条 TLS 会话；热门书评分批请求 20、20、10 条并在 50 条处停止。无划线或书评时服务端可能返回空对象 `{}`，客户端会将其缓存为空列表。Cookie-only Web 接口并非官方开放协议，可能随服务端更新失效；真机联调前可设置 `WEREAD_COOKIE` 与 `WEREAD_BOOK_ID`，运行 `python3 scripts/verify_weread_browse.py` 做脱敏形状验证，脚本兼容 `bestBookMarks` 外层对象和合法空对象，只输出状态、条数和字段存在性。

阅读时长复用现有手动进度同步的 Reader 上下文、TLS 会话和 4 KB I/O 缓冲区，不保持后台 Wi-Fi，也不新增队列或缓存格式。上报值来自刚退出阅读器时的本地会话快照，按整秒向下取整；带时长的 report 若遇到无法确认服务端是否已接收的网络错误，不会自动重复 POST，以降低重复累计风险。

缓存图书时可选择整书，或在章节目录中选择一个闭区间范围。范围缓存生成的 EPUB 仅包含本次所选章节并替换同名旧 EPUB；章节中间文件仍会保留以便后续缓存复用。若微信读书只提供完整 EPUB，非全书范围会提示改用整书缓存，不会忽略用户选择。

## 下载状态与实现边界

下载页显示“缓存图书”，依次展示缓存章节、整理资源、下载图片、生成图书四阶段。章节进度跨越 5% 桶或完成时请求刷新，图片保持 10%；阶段切换立即刷新，准备和打包只显示等待提示，不伪造百分比。200 章连续进度对应约 21 次章节进度刷新请求（不含阶段切换等其他事件），短书仍按章更新。长等待时显示已有的详细提示，底部保留取消。

完整 EPUB 可以在第一阶段直接完成，排除图片可以跳过第三阶段。C3、Sticky 和其他 S3 使用同一套串行流程和 UI；没有新增双核任务或 PSRAM 专属路径。分片合并和 Base64 输入复用 `Operation` 的 4 KiB 缓冲，省去逐章临时 1 KiB 堆分配；Base64 输出写入方式不变，不能据此宣称下载提速倍数。

计时累计使用 `Operation` 内四个 32 位时间字段和一个 64 位字节字段（24 字节字段载荷，对象大小还受对齐影响），不单独申请堆内存。阶段编号和文案由同一个映射提供，四阶段共用绘制出口。`scripts/tests/test_weread_download_ui.py` 编译实际辅助函数和下载绘制分支，检查进度边界、等待提示与 UTF-8 标题截断；字体宽度及绘制使用主机桩，因此不能代替模拟器或真机的横竖屏视觉检查。

## TLS 配置与性能基线

硬件端由固定版本 FreeInk SDK 的 `SecureClient` 统一通过 `HAVE_MAX_FRAGMENT` 申请 2 KiB TLS 记录；应用不再通过 SNI wrapper 重复设置分片。该配置保持原先正常路径的有效申请值，不改变密码套件、X25519 密钥交换或证书验证策略。客户端申请 2 KiB **不代表服务端已经接受**，HTTP 的 4 KiB I/O 缓冲和每次读取长度也不能证明 TLS 记录大小。缺少握手扩展及记录层证据时，协商分片一栏填写“未验证”，不能填写“2 KiB 已生效”。

基线测量复用现有日志，不添加固件采样、任务或缓存：

- SDK 的 `[SecureClient] handshake ok` 输出协议、实际密码套件和握手耗时；同一连接复用不会产生新握手，API 与图片 CDN 的结果分别记录。
- `download performance` 的 `pipelineTotalMs` 从目录获取／章节范围选择完成后开始，包含下载、处理、等待和重试，不含前置登录和目录请求。用户体感总耗时另外从确认缓存到完成提示计时，不与该字段混用。`chapterTransferMs` 包含网络、TLS 和同步落盘；`combineBase64Ms`、`xhtmlMs` 包含 SD I/O，不能当作纯 CPU 耗时；`shardBytes` 包含重试收到的分片数据。图片阶段的已有耗时包含资源整理。
- 使用相同 DEBUG 配置采集现有内存日志和逐章诊断；INFO 配置不会输出这些 DEBUG 数据。`main` 的堆日志包含开机以来的历史最低空闲堆，`WR` 的 `internal/largest/stackFree` 是采样点快照；下载窗口内观测到的最低值不是未采样瞬间的真实最低值。日志缺失时填写“未取得”，不要推算。记录串口是否连接，保持两组日志配置一致。

真机步骤（软件准备阶段不自动执行）：

1. 固定设备、AP、SD 卡、BLE 状态、日志级别、书籍／章节范围和图片策略。文字书、图文书、服务端完整 EPUB 分开记录，先测当前 2 KiB 申请基线。
2. 事先确认测试书 ID 及 `/.crosspoint/weread/<经过文件名清理的 bookId>/` 对应目录，备份并仅移走该书的派生缓存，保留会话、全局书架和其他书籍；不要使用管理页的全局清除缓存。下载会替换同名输出，测试前也要单独备份 `/WeRead` 中该书已有的 EPUB，保留阅读进度。
3. 每轮用相同的重启、联网和进入详情页顺序，确认目标章节／图片冷缓存，再开始计时。每组运行 5 次，保留各次原始结果；成功耗时取中位数，失败单列，不用重跑结果掩盖失败。对比两组时采用相同顺序或交替测试。
4. 记录最终 EPUB 能否打开、所选章节及图片是否正确、实际刷新次数；另行覆盖横竖屏长书名、普通／长等待提示、断网、SD 写失败和取消。分享日志前删除 Cookie、会话标识等敏感信息，不上传 `session.bin`。

## 免责声明

本功能为 CrossMux 提供的非官方第三方功能，与腾讯、微信及微信读书无关。服务可能随官方接口变更而失效。请遵守微信读书用户协议及相关法律法规，并自行承担账号、数据及内容使用风险。

真机传输虽使用 TLS 加密，但由于硬件资源限制，当前不校验服务器 CA 与主机身份，存在中间人攻击风险。请仅在可信网络中使用，并妥善保管保存登录会话的 SD 卡。原生模拟器通过 libcurl 的主机信任库验证证书。更多实现细节见 [统一固件中文支持说明](../../../../docs/engineering/chinese-build.md#weread-transport)。
