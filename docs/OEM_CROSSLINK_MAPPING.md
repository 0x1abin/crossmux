# 官方固件、CrossLink 与模板实现对照

模板不是简单复制任何一个二进制，而是按能力选择证据更完整、实机效果更好的
实现。三份逆向输入的摘要见 [NOTICE.md](../NOTICE.md)。

| 能力 | 官方 EEGO 1.2.7 | CrossLink 1.0.8/1.0.10 | 模板采用 |
|---|---|---|---|
| 电源保持 | GPIO4 启动/睡眠保持 | 同样保持 GPIO4 | 官方与第三方一致的 GPIO4 契约 |
| EPD 引脚/几何 | UC8279C、768×552 + 48 padding | 同控制器和扫描契约 | 共同硬件事实 |
| 黑白刷新 | 可驱动，但用户实测效果和性能较差 | Fast 明显更快，残影控制更好 | CrossLink Fast + 完整清理策略 |
| 四灰阶 | 有完整面板序列 | 有可恢复的 gray drive/LUT | 采用 CrossLink 路径并在模板中单独测试 |
| 触摸固件 | 完整 GSLX680 表 | 固件表逐字节相同 | 相同固件表 |
| 触摸标定 | 覆盖完整边缘的 1.2.7 整数变换 | 短轴覆盖较窄，部分按键/边缘不准 | 官方全范围标定 |
| 屏下键 | 明确 `03a0/1020` 特殊点 | 行为可见但映射不完整 | 官方 sentinel；短按 Back、长按 Home |
| SD | 专用 SPI 引脚可恢复 | 专用 HSPI 调用链清楚 | CrossLink 的独立控制器生命周期 |
| RTC | PCF8563 寄存器与 BCD 语义 | 地址/调用链一致 | PCF8563 驱动，VL 置位时拒绝假时间 |
| 电池 ADC | GPIO10 与分压 | GPIO10、1.559 系数明确 | 第三方系数；百分比只作估值 |
| 充电 GPIO11 | 单机型语义不充分 | 根据 LM3630A population 动态选极性 | 有前光高有效、无前光低有效 |
| 前光 | 共享固件含可选路径 | LM3630A 序列与寄存器清楚 | 先 ACK，再允许低亮度驱动 |
| 中文 | 官方字体/界面支持中文 | CPFONT 字体包支持中文 | 模板用最小 CPFONT reader 验证；产品用 CrossPoint 完整 renderer |
| Wi‑Fi/BLE | ESP32-S3 基础能力 | 有应用使用路径 | Arduino Wi‑Fi + NimBLE，被动扫描后完整释放 |
| 默认休眠 | OEM 产品策略 | 第三方产品策略 | 开发模板默认永不休眠 |

## 选择规则

1. 引脚、控制器地址、特殊按键和休眠电源状态优先采用可交叉确认的硬件事实。
2. 两份固件不一致时，优先采用覆盖范围更完整且能由实体机复核的实现。
3. 性能策略采用实机效果更好的 CrossLink 刷新方案。
4. 未装配的可选电路必须 runtime probe，不因共享固件含驱动就宣称存在。
5. 没有调用链、ACK 或板上证据的音频、麦克风、LED、IMU、环境传感器不驱动。

## 如何参照两套固件开发

- 想保持 OEM 操作习惯：使用官方触摸标定、侧键语义、屏下键 sentinel、
  PCF8563 和 GPIO4 电源契约；模板已封装这些行为。
- 想获得第三方固件的体验：使用 Fast/Full cadence、专用 SD SPI、
  MiSansA4 CPFONT 和动态前光/充电分支；模板也已封装。
- 想写新的阅读器应用：不要直接使用诊断用单行 `CpFontRenderer` 做产品排版。
  应复用 CrossPoint 的缓存、fallback、kerning、BiDi、换行和灰阶抗锯齿路径。
- 想支持新硬件 revision：先保存 I²C 扫描、GPIO 空闲电平、触摸角点和完整 Flash
  备份，再修改 profile；不要只凭外观或商品页面猜测。

原始函数、地址、引脚和置信度的更细说明见
[HARDWARE_REFERENCE.md](HARDWARE_REFERENCE.md)。
