## B：RTC 与共享总线

开始前的只读探测实际读到 TESTC=1、VL=1：初始日历不可信，未采用它校准系统时间。
依据 [NXP PCF8563 数据表 8.3.1/8.11.1](https://www.nxp.com/docs/en/data-sheet/PCF8563.pdf)，
修正版仅在明确写入可信时间时清除 TESTC 复位覆盖位；begin/now 继续只读并拒绝
STOP、测试模式、VL，TEST1 外部测试时钟模式仍禁止写入。原 2026-11-10 RTC 候选
从未刷入，保留作历史产物。修正版 37 个原生 RTC 用例和 17/17 Plus CTest 通过，
应用区写入校验通过，三段受保护区域校验匹配。已确认的休眠范围及暂缓项目见下文。

用户已确认本次联网校时界面显示成功，时间与手机一致。原 900 秒采集已在用户校时前
结束，没有覆盖当次 RTC 写入/读回日志，故另外做了独立硬件复核。用户退出校时页后
报告没有重启、时间正确；Plus 的触屏分支会停止 Wi-Fi 而不重启
（`src/main.cpp` 的 `finishWifiSessionWithoutRestart`），不能视为重启验收。
随后 Mac 核对当前固件/受保护区后普通重启，日志系统时间为本地 22:50。该启动
`RTC clock read` 标签实际读取系统时间，系统时间可能跨重启保留，不能单独证明外部 RTC。

已有只读探测程序随后直接读到 PCF8563 的 `control0=00`、VL 清除，以及 UTC

不写日历/NVS/SD，独立确认了可信校时已写入硬件、UTC 约定正确且秒数推进。
证据为外部 `logs/plus-rtc-trusted-readback-20261112.json`。完成后切回同一 RTC＋灰阶版。
随后串口还捕获到固件自身的 `External RTC set to 2026-11-12 14:58:33 UTC` 和
