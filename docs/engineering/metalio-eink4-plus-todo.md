# Metalio E-Ink4-Plus：剩余适配与验收

更新：2026-11-09。适用硬件为 **V1.4 / ESP32-S31 rev 0**；不能套用到
ESP32-S3 的 `metalio_eink4`。硬件、实现和历史实验见
[设备记录](metalio-eink4-plus.md)。本表区分尚未接入的功能与已经实现、仍需验收的路径。

## 当前可用基线

以下项目已经在这台 V1.4 设备上由用户操作确认，范围限于记录中的场景：

- 原生 1216×684（竖屏 684×1216）显示；高密度界面字体和底部图标大小、点按正常。
- 打开 EPUB、中文显示、触摸、盖板 Home/翻页键、音量键翻页；阅读位置和设置在重启后保留。
- SD 挂载和阅读；普通文字翻页使用差分刷新，按设置周期全刷清理，菜单和唤醒后显示正常。
- 前光亮度、色温、开关和设置保留；电量/充电状态只读显示。
- 电源键手动休眠/唤醒三轮后，SD、阅读位置、翻页和 Home 正常。
- STA 局域网 Wi-Fi、HTTP/mDNS、网页 HTTP/WebSocket 文件传输，以及上传 EPUB 后阅读。

自动休眠仍设为“永不”。当前显示输出为黑白；界面放大不等于已接入灰阶或文字抗锯齿。
电量显示正常不代表已校准容量，也不证明续航。固件保留在设备上，仅在用户要求时还原。

## 待办与验收条件

P1 为日常使用优先项，P2 为质量或可选能力，P3 为按需求选择的扩展。
发布前门槛单独标记，不把所有可选功能都视为发布前提。

| 优先级 | 工作项 | 当前状态 | 下一步与验收条件 |
|---|---|---|---|
| P1 | RTC 硬件时钟 | 尚未接入 | 核对本版 RTC 接线/芯片，复用现有 native I2C1 的唯一所有者和锁；不能直接启用使用 Wire/Wire1 的通用驱动。验证联网校时、断网、重启、休眠后的时间保持，保留无关控制/闹钟状态。 |
| P1 | 自动休眠 | 手动路径已验收；自动路径待验收 | 保持“永不”直到受控测试。分别验证阅读/菜单超时、输入和传输活动阻止误休眠、超时后唤醒、阅读位置、SD、前光及一次按键只触发一次动作。 |
| P1 | 电源、续航与电量准确度 | 只读遥测已接入；测量待做 | 验证纯电池冷启动、USB 拔插、低电状态和多轮唤醒；记录供电条件、活动/休眠实测电流、持续时间与电压/SOC 趋势。现阶段不写充电器配置或电量计校准参数。 |
| P2 | 灰阶图片/封面 | 尚未接入；能力关闭 | 建立灰阶缓冲、驱动能力和刷新策略；验证连续灰阶页、灰阶到菜单/文字、周期全刷、故障恢复，测残影和刷新耗时，并单列内部 RAM/PSRAM 峰值。 |
| P2 | 文字抗锯齿 | 尚未接入 | 与图片灰阶分开评估。对比中文/拉丁字形、不同字号的清晰度、残影和翻页时间；保留已验收的黑白差分路径作为回退。 |
| P2 | USB 大容量存储（MSC） | `FREEINK_CAP_USB_MSC=0` | 先设计读卡所有权：主机挂载时停止固件侧 SD 访问，退出/安全弹出后重挂载。验证热拔插、传输中断、休眠限制和文件完整性，再考虑开放能力。 |
| P2 | 网络兼容性 | STA 局域网传输已验收；其余待验收 | 受控测试 AP/热点、Calibre、实际需要的公网 TLS 服务、失败提示及退出后阅读恢复。先测试现有实现，有缺陷再修改；不预设全部需要新驱动。 |
| P2 | 完整显示/阅读回归 | 已实现的部分路径待验收 | 覆盖四种方向及触摸边缘、其他主题、图文/大书、菜单叠层、长时间连续翻页和多轮休眠；分别记录错位、截断、残影、内存趋势及失败恢复。 |
| P2 | BOOT61 与恢复手势 | 实体按压/恢复流程待验收 | 先核对启动/恢复契约和已备份分区，再测试短按/长按及组合手势。不能把现有备份中的救援镜像视为已验证可用。 |
| P3 | 自动旋转 / IMU | `NO_SENSORS`，尚未接入 | 先核对本版实际传感器及总线，再接入方向事件；验证旋转、触摸映射、按键含义和阅读位置，测后台功耗。 |
| P3 | BLE 翻页器 | `FREEINK_CAP_BLE_HID_HOST=0` | 核对 S31 当前工具链/协议支持及资源成本，再测试配对、重连、按键去重、休眠和关闭时资源释放。 |
| P3 | 音频 / 麦克风 | `NO_AUDIO` / `NO_MIC`，尚未接入 | 按实际硬件和用户需求单独决定范围；核对引脚/供电冲突、驱动与资源预算，不作为当前阅读功能验收门槛。 |
| 发布前 | SDK 合并与依赖固定 | SDK 改动单独投稿，尚未集成 | 先合并关联 SDK PR，再将 CrossMux gitlink 更新到配置的 SDK 源仓库中已集成的提交；比较源码树与测试版本，按差异补验证。此前 CrossMux 保持 Draft。 |
| 发布前 | 兼容构建、静态检查和完整 CI | 尚未全绿 | 补齐原有 C3/S3 构建矩阵；处理/核实主机夹具和 cppcheck 包含路径问题，保留基线对比，不能将失败或未运行标为通过。缺少依赖时先获得安装授权。 |
| 发布前 | 标准刷写、OTA、公开发布 | 常规上传被构建保护阻止；未加入发布 | 在具体分区/备份/恢复方案下验证标准安装、升级、错板拒绝、失败回退和应用槽边界。另行决定 Nightly/OTA/Web 注册，不能因开发构建可用就自动发布。 |

用户明确暂缓“休眠唤醒后偶尔需要重新插 USB 线”的调试。它属于串口重新枚举问题，
与尚未开放的 USB MSC 是两个工作项；后续按用户需要重新排期，不阻塞当前阅读调试。

建议下一轮先做 RTC，再验证自动休眠与功耗；如果更重视字形/封面观感，则先做灰阶和文字抗锯齿。

## 复现与依赖状态

CrossMux 适配在 `codex/metalio-eink4-plus-s31`，界面密度提交为
`0ff46be41079faf00b063d66d5439533f9323986`。
已测试 SDK 为 `3cb3d568e3fe5c9d69d1ba47eb8dfdb64d34610d`，同名分支；
它尚未合并到配置的 `0x1abin/freeink-sdk`。

投稿期间保留源仓库已有 SDK 基线 `d9a1304cd234b0536136302f629304b609f62b32`，
不把仅在个人 fork 中的提交作为默认子模块依赖。**默认检出的 SDK 不能构建 Plus**；
需要测试本 PR 时，先手动检出临时 SDK，以下测试也只代表这个临时组合：

```sh
git submodule update --init --recursive
git -C freeink-sdk fetch https://github.com/lfxyl/freeink-sdk.git codex/metalio-eink4-plus-s31
git -C freeink-sdk checkout --detach 3cb3d568e3fe5c9d69d1ba47eb8dfdb64d34610d
git -C freeink-sdk submodule update --init --recursive
pio run -e metalio_eink4_plus
```

这会有意使本地 SDK 检出与已提交 gitlink 不同；不要将临时 gitlink 再次提交。
SDK 合并后，以实际集成提交替换这段临时步骤。完整的主机检查和本地隔离工具链说明见
[设备记录的复现部分](metalio-eink4-plus.md#reproduce)。常规 `upload` 仍由保护脚本拒绝。

## 已有证据与限制

以下为本轮文档提交之前的已有测试记录，本次迁移和文档整理未重新刷机：

- 最近 S31 高密度界面固件构建通过：静态 RAM 108,032 字节，链接 Flash 6,509,170 字节；
  BIN 6,510,016 字节，SHA-256
  `3b55b6e033382f7cdef98e16ce7ceb243ba63e23174e98bd65955261dd1383d1`。
- 最近完整主机 CTest 为 **1,532 / 1,538**。六个失败项为 `WeReadConnection`、
  `ReadingUiRegressions`、`UiFontFallback`、`FileBrowserImages`、
  `WebServerStartupFailure`、`FirmwareUpdateRefresh`，与原基线的编译错误集合一致；
  另有独立 ReadPico chrome 夹具的 Apple clang `-Werror` 失败。
- C3/S3 全固件构建矩阵未运行；严格 cppcheck 受 IDF 包含路径影响，结论不完整。
  不能据此宣称完整 CI 通过或原设备均已回归。
- 差分刷新和高密度界面有用户实机反馈；灰阶、全方向/全主题、续航、长期稳定性仍待验收。
- 设备备份、串口日志和用户书籍保存在仓库之外，不随 PR 上传。
